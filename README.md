# Pre-Season

**Personalized pre-season training plans for footballers.** Tell Pre-Season your position, fitness, kit, timeline, and any injuries, and it builds a periodized multi-week plan that ramps you from base fitness to match-ready. Free plans come from a deterministic in-app engine; an AI season pass unlocks unlimited plans generated by Claude.

**Live:** https://pre-season-app.vercel.app

**Stack:** React 19 + TypeScript + Vite • Supabase (Postgres + Edge Functions) • Clerk auth • Anthropic Claude API • Stripe • deployed on Vercel

---

## The product

Amateur and semi-pro players usually come back for pre-season with no real structure: a generic PDF, a few half-remembered drills, and a high chance of pulling something in week one. Pre-Season replaces that with a plan built around the individual.

A player answers seven short questions and gets a periodized plan organized into Foundation, Build, Peak, and Taper phases, with sessions matched to their position, available equipment, weekly time, and a goal such as endurance, speed, or strength. Declared injuries are worked around automatically. As the season progresses, the player ticks off completed sessions and the dashboard surfaces what to train today.

It ships in two tiers:

- **Free.** A smart, periodized plan from an in-app generation engine. Position-aware and injury-aware.
- **AI season pass.** A one-time payment unlocks unlimited AI-generated plans for the length of the season, so a player can regenerate freely as their fitness, schedule, or goal changes.

The app localizes itself to the visitor: UK and Ireland see "football" and pricing in pounds, Canada and the US see "soccer" and dollars, all detected automatically with no location permission prompt.

## Who it is for

Returning club, university, Sunday-league, and academy footballers who want a structured run-up to the season without paying for a personal coach.

## How it works

1. **Onboard.** Seven steps capture position, fitness level, season length (4, 6, 8, or 10 weeks), weekly availability, equipment, injuries, and primary goal. Region is detected, not asked.
2. **Generate.** The free engine produces a periodized plan instantly. With an active season pass, the plan is generated by Claude behind a serverless function.
3. **Train and track.** The dashboard shows the current week, highlights today's session, and records completions.
4. **Upgrade when ready.** Buying a season pass is a single Stripe checkout, priced by season length and local currency.

## The season pass (commerce model)

Premium is a one-time purchase rather than a subscription. A completed Stripe Checkout grants a pass that unlocks unlimited AI plan generations for the length of the player's season, computed as the purchase time plus the chosen number of weeks. When the season elapses, a new purchase is needed, and regenerating within an active pass is free.

Pricing is a 3-by-4 matrix: three currencies (CAD, GBP, USD) across four season lengths, backed by twelve one-time Stripe prices and mirrored in the frontend display strings so the badge a user sees always matches what Stripe charges.

Both generation paths emit the same `TrainingPlan` shape, so the renderer never needs to know whether a plan came from the deterministic engine or the model.

## Engineering highlights

- **Two engines, one contract.** The free deterministic generator (`planGenerator.ts`) and the Claude-backed generator both produce an identical typed `TrainingPlan`. The deterministic engine builds plans from a roughly 70-exercise tagged library with stable rotation, so the same inputs always yield the same plan, and a structured contraindication filter removes exercises by the body part they load rather than by string-matching their names.

- **Capability-token gating for paid AI.** AI generation cannot be triggered without an active pass. A `SECURITY DEFINER` Postgres function, `claim_ai_generation()`, mints a token only while the caller holds a paid, unexpired pass, and the generate function re-validates that token server-side before calling Claude. Payment state is owned entirely by the Stripe webhook, never the client.

- **Third-party auth into row-level security.** Clerk issues the JWT; Supabase verifies it through its third-party auth integration, and every table enforces owner-only access via `auth.jwt() ->> 'sub'` matched to `users.clerk_id` through a `current_user_id()` helper. Because Supabase's gateway will not verify Clerk tokens directly, Edge Functions are invoked with the anon key and user identity flows through Postgres RPCs instead, which keeps server-side secrets off the client while still scoping every write to the right user.

- **Multi-currency one-time payments.** A `create-checkout` Edge Function reads the season length from the user's saved preferences server-side (so it cannot be spoofed), selects one of twelve Stripe prices, and records a pending purchase. A signature-verified `stripe-webhook` flips it to paid and stamps the expiry. The Stripe SDK runs on Deno's fetch-based HTTP client with the subtle-crypto provider for async signature verification.

- **Localization without tracking.** Region is inferred from the browser time zone with a locale fallback, never an IP lookup or a location prompt, then drives currency and the football-versus-soccer vocabulary across the app.

- **Privacy by design.** Row-level security is owner-only on all tables. Users can export every row tied to their account as JSON and delete their account in one action, which cascades the database rows and removes the Clerk identity. Injury and fitness data is treated as health information, gated behind an explicit consent step whose timestamp is recorded for accountability.

- **Typed JSON contract for the LLM.** The model returns structured JSON validated against the plan schema before it is persisted or rendered, so model output is never trusted blindly into the UI.

## Running locally

### Prerequisites

- Node.js 20+ and npm
- A Supabase project and a Clerk application (free tiers are fine)

### Setup

```bash
git clone https://github.com/MBM-M/pre-season-app.git
cd pre-season-app
npm install
```

Create a `.env` in the project root:

```env
VITE_CLERK_PUBLISHABLE_KEY=pk_test_...
VITE_SUPABASE_URL=https://<your-project>.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
```

Run the SQL files in the Supabase SQL Editor to create the schema and apply the incremental migrations (purchases, completions, plan start date, health consent, and the row-level-security policies).

```bash
npm run dev       # http://localhost:5173 with hot reload
npm run build     # production bundle
npm run lint      # lint
```

### Enabling the AI season pass (optional)

The free tier runs with no extra setup. The paid tier additionally needs the three Edge Functions deployed and their server-side secrets configured: `ANTHROPIC_API_KEY`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, an `APP_URL`, and the twelve `STRIPE_PRICE_{CURRENCY}_{WEEKS}` price IDs. Each function's header comment documents the secrets it expects.
